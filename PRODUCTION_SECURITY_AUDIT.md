# ShopBD production security audit

Scope: release branch and disposable loopback services. This is a source review plus targeted tests, not a penetration test or a certification. Do not expose a deployment until the [Phase 6 release blockers](PHASE_6_PRODUCTION_READINESS_REPORT.md) are resolved. Production infrastructure was not inspected.

| Area | Verified controls and limits | Status |
| --- | --- | --- |
| Authentication and RBAC | Credentials DTO and bcrypt byte limits; portal-specific role; short-lived encrypted JWT backed by hashed DB session handle; live role/block/version/expiry checked in application guards and independent admin actions/handlers. Auth version trigger and DB revocation on logout/credential change. Proxy check is only an early redirect. No MFA. | **PASS** in local DB suites; **MANUAL ACTION REQUIRED** for real ingress and admin access policy |
| Password recovery | Generic eligibility response, provider optional but fails closed when not configured, no public admin self-reset; one-use hashed token with expiry, fragment delivery, version/consume/update/revocation transaction. Mock transport tested by DB suite. | **PASS** for local policy; **NOT TESTED** for live Resend |
| Shared abuse limits | Parameterized PostgreSQL fixed windows use the DB clock and HMAC identifiers. Independent Node processes using the same DB and secret consumed only five allowed requests against a five-request bucket. Guards handle failures without granting access. Per-IP use depends on ingress rewriting one trusted header. | **PASS** for storage/cap behavior; **MANUAL ACTION REQUIRED** for shared production secret, edge limits, trusted header and cleanup schedule |
| Receipts and ownership | Authenticated reads scope on `Order.userId`; delivery phone never grants identity. Guest receipt uses digest, expiry and anonymous-order predicate. Scope cookie is separate from receipt grant; minimal view omits delivery/identity details. Never share receipts in CDN or observability. | **PASS** in local SQL regression and HTTPS fixtures; **MANUAL ACTION REQUIRED** at target edge |
| Checkout, coupons and inventory | Validated district/zone/COD/discounts; current quote and Decimal totals; serializable bounded retries, buyer-bound idempotency and conditional inventory/coupon writes; unique idempotency/redemption keys; transactional cancellation restores stock once. No display cache authorizes a purchase. | **PASS** in core commerce regression; **NOT TESTED** through hosted pooler/production concurrency |
| Media | Independent live admin + same-origin checks, request/file/decoded-pixel bounds, signature and re-encode, no physical file deletion by clients. URL allowlist, redirects and local-IP optimizer fetch disabled. Durable UploadThing required in production. Test benign image round-trip with provider (development fallback does not count). | **PASS** for local acceptance/rejection logic; **NOT TESTED** for live storage |
| CSV | Live admin and audit, bounded export, formula-safe text encoding, `private, no-store`. Exports contain operator-required customer data: authorize, retain and distribute separately. | **PASS** for local authorization/format logic; **MANUAL ACTION REQUIRED** for operator policy |
| Headers and caches | Existing boundary CSP (`base-uri`, `object-src`, `frame-ancestors`, `form-action`), no sniffing, referrer controls and Secure cookies preserved; private route `X-Robots-Tag`/no-store unchanged. CSP does not constrain all scripts; no nonce-based policy or HSTS assertion at the app. Configure HTTPS/HSTS and cache rules at ingress. | **PASS** for local response headers; **MANUAL ACTION REQUIRED** to verify on deployed edge |
| Logs and public SEO | App error helpers classify details without recording request/payload; proxy and browser diagnostics log fixed production categories. Metadata/JSON-LD uses public store values, live products and published reviews; nothing reads account, checkout, or receipt records for public discovery. Moderators must remove personal information from review texts/display names before publishing. No tool captured all framework/host logs; verify scrubbers at ingress/APM. | **PASS** for targeted checks; **NOT TESTED** for host telemetry/retention |
| Dependencies | `npm audit --omit=dev` initially flagged 10 package entries (nine high/one moderate). Updated PostCSS and resolved Browserslist/Lodash, and removed unused UploadThing React bindings. Repeat audit: **five high, one moderate, no critical** package entries; the underlying Effect/`@effect/platform` advisories remain via Prisma tooling and UploadThing. Package totals include transitively flagged dependents, not six independent exploit findings. npm suggested incompatible major downgrades, not safe fixes for this release. No exploitability claim is made either way. | **FAIL** open dependency review gate; do not force audit fixes |

## Ordered pre-release sign-off

1. Review remaining advisory routes and reachability with the exact lockfile and hosted configuration. Prefer supported upstream versions; if none, document business impact, compensating controls, ownership and expiry for any explicit acceptance. Rerun both runtime and full-tree audits on the release runner; keep migration tooling restricted to the build/ops environment.
2. Provision individual admin accounts, rotate any legacy credentials, restrict admin ingress where compatible, confirm operator recovery and secret/session-rotation process, and review MFA policy. Audit prior-order associations without relinking by phone. Review already-cached receipt/data URLs if upgrading an old deployed app.
3. Apply edge controls, verify spoofed/untrusted forwarded headers cannot affect host or trusted client IP policy, and test private cache separation with two browsers. Record authorized results without reference numbers or credential/cookie values. Do not deploy framework builds configured with development TLS or permissive origins.
4. Run live **staging-only** provider, backup/restore and smoke checks. Verify log redaction and alerts for DB failure, elevated authorization failures/throttling, mail and media errors. Add only the minimum user-consented tracking configuration; no tracking scripts are part of this phase.
