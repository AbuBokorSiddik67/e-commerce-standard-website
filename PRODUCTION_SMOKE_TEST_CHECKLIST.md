# ShopBD staging release smoke checklist

Use only synthetic fixtures and a disposable DB on an approved staging ingress. Separate the guest, shopper A, shopper B and admin browser profiles. Record revision, host, browser, time, assertion outcome and owner; never record passwords, tokens, receipt capability details, addresses or provider keys. Write PASS, FAIL, BLOCKED, NOT TESTED or MANUAL ACTION REQUIRED next to each item.

1. **Startup/infra:** Replay migrations with native Prisma (repeat should be a no-op); production build and start with valid configuration. In a separate disposable worker verify startup refuses missing secret/mismatched origin. Check live/ready 200, DB outage ready 503/live 200, readiness recovery, graceful drain/roll replacement, and alert activation. Use a synthetic stage failure only.
2. **HTTPS/cache/SEO:** Request HTTP and alternate hosts; expect canonical HTTPS or rejection. Inspect security headers and cookie attributes (not values). Compare HTML/RSC/account/cart/checkout/admin/receipt/CSV in separate sessions through the CDN; private responses must not be cache hits. Verify home/category/product canonicals, facets `noindex`, robots, XML sitemap and a valid shard/invalid shard, social data and approved-only structured data. Check no customer or private routes in public discovery. Confirm public settings/category changes and product archive invalidate relevant data across replicas. Confirm uploaded and checked-in media optimize from allowed hosts; no guessed canonical origin or stale staging domain in live builds.
3. **Authentication:** Register and sign in; verify incorrect credentials fail generically and admin/customer route roles are separated. Check password reset from authorized staging Resend with known and unknown addresses, fragment link and one-time redemption, session revocation and logout. Test a cross-replica identity limit using a designated account and agreed test rate. Validate `AUTH_CLIENT_IP_HEADER` with the traffic owner; do not run high-volume abuse tests on a public host.
4. **Shopping:** Search for a real fixture, filter by category and sort, choose a valid variant, add to cart and edit quantity. Try invalid/expired coupon and apply the valid staging coupon; confirm discount and correct fee after selecting a mapped district. Place one guest COD order and one authenticated order. Review total, simulate a price/stock change and confirm the old approval cannot commit silently. Check retry of the same intent and that available stock decrements exactly once in the service tests. No payment provider is expected.
5. **Ownership and tracking:** Signed-in buyer sees only own purchase in history/details; another buyer and a fresh guest cannot open it. Anonymous receipt is browser-bound, expires, contains no contact or delivery PII, and does not leak to a second session. Track the synthetic order with its reference and phone; wrong phone must not reveal it. Negative request results must not redirect to a public copy of private content.
6. **Operations:** Admin edits a product/media/variant stock, confirms an order and cancels an eligible unpaid synthetic order, with one inventory restoration and audit entry. Publish and hide a test review; aggregate ratings/schema update, pending content remains absent. Admin can export permitted dates as CSV without a shared cache; customer/cross-site requests are denied. Test actual file-size limits and provider callback/response behavior on the hosting plan. Confirm support contact opens an email draft or provides the published alternate contact channel, never claims delivery to the support inbox.
7. **Accessibility/responsive:** Use keyboard only to skip to main, search and select variants, handle dialogs (Escape and focus return), use review and checkout fields, and read errors with labels and live feedback. Inspect contrast including merchant-specific palette, 200% zoom and focus visibility. Inspect reduced motion and carousel handling with real configured banners. Test 320/390/768/1024/1440 CSS px on public and key admin flows, then repeat important tasks in Chromium, Firefox and WebKit/Safari with screen-reader coverage where available. Automated checks and a limited keyboard review do not establish WCAG conformance.
8. **Go/no-go:** Capture health/error baseline and review backup recovery, provider tests, unresolved advisories, accessibility limits and before/after performance. Run representative Lighthouse and real-user monitoring in staging and after authorized release; no claim about field INP or Google indexing without field evidence. Require outcome sign-off from database, security and store operators before any live change.
