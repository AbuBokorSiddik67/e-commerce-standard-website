## A. Project Overview

**ShopBD** is a single-store Bangladeshi e-commerce application for catalog discovery and cash-on-delivery (COD) orders. Customers can shop as guests or create accounts. A separate admin interface handles merchandising, catalog, stock, customers, and fulfillment. The package name is the generic `nextjs`; ShopBD is the documented product name and default brand. Checkout, admin, and persistence run in the same Next.js application, not a separate API deployment.

## D. Existing Features

- **Storefront:** Configurable hero/promotions, trust strip, category showcases, new arrivals, best sellers, featured products, social tiles, reviews and newsletter/WhatsApp CTA; faceted catalog; product details, variants, image gallery, related products; cart, coupons, COD checkout, confirmation and tracking; branded About/Contact/policy pages; sitemap and product JSON-LD.
- **Customer:** Credentials registration/login/recovery screens, profile edit, address CRUD/default selection, saved products, protected order list/detail, tracking link, review submission. Some displayed or submitted behaviors are incomplete, as detailed in E.
- **Admin:** Dashboard, catalog and image management, bulk product controls, category tree, orders and status controls, manual payment flag, printable order view, CSV export, customer detail/block toggle, coupon and banner CRUD, homepage editor, branding/policy/COD settings, delivery zones, reporting and some audit events.
- **Reliability/security already present:** Prisma stock predicates and transaction on order creation; unique order/idempotency identifiers; server-calculated base prices and fees; password hashing, hashed reset tokens, role gates on privileged surfaces, order fit-and-finish error boundaries, some rate limiting and response headers. These controls are real but do not close the gaps in G–I.

## I. Security Issues

These are defensive findings from source inspection, not evidence that this application was deployed or exploited. No stored/customer data, password values, tokens or connection strings are included. **Critical** here is a release gate for an authorization design that can disclose private order data if deployed; practical exposure depends on real records and access paths.

| ID | Severity | Issue and paths | Recommended solution | Expected impact |
| --- | --- | --- | --- | --- |
| I-01 | **Critical** | Public confirmation route loads an order solely by its display order number and renders item/amount/status and delivery address without checking session ownership, phone or a receipt capability. Order number generation is designed for business reference, not authorization. `src/app/(shop)/order-success/[orderNumber]/page.tsx`, `src/lib/utils.ts`, `src/components/customer/checkout-client.tsx`. | Require authorized order ownership for account receipts; for guests use a scoped, high-entropy expiring receipt grant or verified in-session receipt. Minimize fields, prevent public cache/indexing, and verify unauthorized links cannot return private data. | Closes direct unauthorized access to customer delivery information. |
| I-02 | **Critical** | Checkout chooses `Customer` using an OR of unverified delivery phone and session user ID. It can associate a guest or a different customer's order with the wrong customer row, or collide with unique `Customer.userId` during linking. Account history/details authorize via `Order.userId OR Customer.id`, so a misassociation can disclose full name, phone, address and notes. `src/server/services/{order,account}.service.ts`, `src/app/(shop)/account/orders/[orderNumber]/page.tsx`, `prisma/schema.prisma`. | Separate a delivery phone from account identity. For account orders use the authenticated user as owner; keep guest orders unclaimed until verified ownership, not phone-string equality. Review/backfill inconsistent associations and test tenant isolation before deploying. | Prevents disclosure of another person's order data and stabilizes guest/account linking. |
| I-03 | High | README and seed contain a known demo admin default; seed upserts it without an environment safety guard. Existing users aren't overwritten by that upsert, and production use was not inspected. `README.md`, `prisma/seed.ts`, `package.json`, `prisma.config.ts`. | Remove reusable production-reachable defaults, isolate demo seed with a hard environment guard and use a secure one-time admin provisioning flow. If ever seeded beyond development, rotate/remove and review privileged access. | Avoids predictable admin accounts on deployed stores. |
| I-04 | High | JWT role is copied at sign-in; shared guards/actions and upload/export rely on claims without checking account state. Admin blocking changes records but doesn't revoke existing JWTs, and guest checkout doesn't consult the business block flag. Partial updates can desync user/customer block state. `src/lib/{auth,auth.config,auth-guard}.ts`, `src/proxy.ts`, `src/server/{actions,services}/`, `src/app/api/{upload,admin/orders/export}/route.ts`. | For protected actions verify active principal/current role or session version; revoke on credential, role or block changes. Make the identity-state write atomic and define a separate abuse policy for unverified guest phone numbers. | Timely revocation and consistent access enforcement. |
| I-05 | High | Direct credentials authorization has no throttle; selected actions use a process-local map keyed by the forwarded header without trusted-proxy normalization or key eviction. That is not a reliable shared control across instances; actual header trust depends on deployment. `src/lib/{auth,rate-limit}.ts`, `src/server/actions/{account,customer}.ts`. | Rate-limit provider login, reset and order lookups using trusted normalized signals and shared TTL storage; add bounded keys, monitoring and privileged MFA, balancing false positives. | I-06 | High | Production password reset responds successfully without sending a link. | I-08 | Medium | Upload trusts file-declared MIME, parses all multipart first, lacks app-level file-count/total-byte/dimension checks and can leave files on partial failure. Admin check, UUID names and per-file limit are positives; real platform limits may differ. `src/app/api/upload/route.ts`, `src/lib/constants.ts`, `next.config.ts`. | Enforce upstream/request bounds and runtime File checks, sniff and re-encode allowed image formats, bound decoded dimensions, apply quotas, and clean up partial writes. | I-09 | Medium | Image optimizer accepts wildcard HTTP/HTTPS hosts; admin-configured href/media and flexible homepage settings have inconsistent protocol/host validation. **Cross-cutting checks:** No raw query calls were located in `src`/`prisma`; inspected data access uses structured Prisma inputs, so no direct SQL injection was confirmed.
